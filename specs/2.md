Problem
Starboy's CLI has no way to verify that the `starboy` command is installed correctly and runnable in a given environment. Developers, CI pipelines, and automation wrapping Starboy need a fast, dependency-free way to confirm the executable is on the path and functioning before invoking heavier commands.

Scope
- Add a new `starboy health` subcommand to the CLI (src/starboy/cli.py).
- The command prints exactly `ok` followed by a single trailing newline to stdout.
- The command exits with status code 0 on every invocation.
- The command performs no I/O beyond writing to stdout (no file reads, no network calls, no environment inspection).
- Add automated test coverage for the command in the tests suite (e.g., tests/test_cli.py or equivalent), invoking the CLI entry point and asserting on stdout content and exit code.
- Register the command in any CLI help/usage listing so it appears alongside existing subcommands.

Out of scope
- Network or connectivity checks (e.g., pinging external services, checking API reachability).
- Checks of external service dependencies (databases, GitHub API, agent runtimes, etc.).
- Verbose or structured health output (e.g., JSON, version info, diagnostics) — output must be exactly `ok`.
- Non-zero exit codes or failure modes for the health check itself.
- Any configuration options or flags for the `health` command.

Acceptance criteria
- Running `starboy health` writes exactly the bytes `ok\n` to stdout, with nothing else written to stdout or stderr.
- Running `starboy health` exits with status code 0, verifiable via `echo $?` immediately after execution.
- Running `starboy health` with no arguments succeeds; running it with any unexpected extra arguments either is rejected by the CLI's standard argument-parsing error path (non-zero exit, matching existing subcommand behavior) or is ignored — whichever matches the existing CLI framework's default behavior for other subcommands (must be consistent, not special-cased).
- `starboy --help` (or equivalent top-level help output) lists `health` as an available subcommand.
- An automated test exists that invokes the `health` command programmatically (not via shell subprocess unless that is the existing test pattern in the repo) and asserts both the exact stdout output (`ok\n`) and the exit code (0).
- The test suite passes running the full existing test command (e.g., `pytest`) with the new test included, with no modification to unrelated passing tests.
- No new dependencies (network libraries, HTTP clients, etc.) are added to the project's dependency list as part of this change.
